# Fin — デザイン生成用プロンプト集

作成: 2026-08-02
用途: Claudeでアプリ画面のデザイン案を作るためのプロンプト。オーナーが叩き台を複数生成して選ぶ。

使い方: **「共通プロンプト」を毎回先頭に貼り、その後ろに「画面別プロンプト」を1つ足す。**

> **先に `asset-prompts.md` でカラーパレット・アプリアイコン・タスクアイコンを作ってください。**
> 素材を添付した状態で画面デザインを作らないと、文字だけの安っぽい画面になります。
> 素材ができたら、共通プロンプトに「添付のアイコンとパレットを使用してください」を足して使います。

---

## 共通プロンプト（毎回先頭に貼る）

```
iOSアプリ「Fin」の画面デザインを作ってください。実際に動くHTMLモックアップとして、iPhone実機サイズ（393×852pt）で作ってください。

## アプリの説明
タスクに「何分かかるか」の見積もりを入れると、全部終わる予定時刻が表示されるタスク管理アプリ。実行中は1タスクだけを大きく表示してカウントダウンし、完了するまで次に進まない。主なユーザーはADHD当事者と、先延ばしに悩む人。

## 世界観：責めない
最重要の原則。ユーザーは「またできなかった」という自己嫌悪を日常的に抱えている。詰めるアプリは、一番助けが要る日に開かれなくなる。

- 急かさない、煽らない、減点しない
- 連続記録やストリークを目立たせない
- 未達を赤字や警告色で表示しない
- 静かで、余白があり、落ち着いている
- 名前のFinは映画の終わりに出る「Fin」から。静かな余韻を持たせたい

## スクショ映えの要件（通常のアプリ設計と判断が逆になる部分）
この画面はXのタイムラインに小さく表示される。そこで意味が伝わらなければ意味がない。

- **1画面に主役を1つだけ置く。** 特に終了予定時刻の数字は、画面の主役として極端に大きく
- **情報密度を上げない。** 縮小表示で潰れる。余白を大胆に取る
- **コントラストを強く。** サムネイルで目立つこと
- **説明文なしで意味が伝わること。** 文字を読ませない
- 一般的なToDoアプリのような「グレーの行が並ぶ」見た目は避ける。縮小すると何も伝わらない

## 制約
- iOSネイティブらしい操作感（SF Pro系のフォント、iOS標準のジェスチャ）
- **ライトモードを基本とする（白基調）。配色は任せるが、赤字・警告色など「詰めている」印象を与える色は使わない**。ダークモードも用意
- 日本語UI
- 絵文字をタスクに付けられる
- 医療的な表現は使わない（「治療」「症状」「改善」などは禁止。生活支援として書く）

## 出力
配色・タイポグラフィの意図を短く説明したうえで、HTMLモックアップを出力してください。
```

## 画面別プロンプト

### 1. ホーム画面（最重要・スクショの主役）

```
【画面1: ホーム】

今日のタスクが並び、画面上部に「全部終わる予定時刻」が表示される。

要素:
- 終了予定時刻（例: 19:40） ← この画面の主役。極端に大きく
- 合計時間（例: 3時間20分）
- タスクのリスト（絵文字＋タスク名＋見積もり分数）
- タスク追加ボタン
- 「今日はやらない」に退避したタスクへの導線

最重要: この画面のスクリーンショットが、SNSで「これすごい」と思わせる絵になること。
「19:40」という数字が主役として立っていて、それ以外の要素が邪魔をしていない構成にしてください。

3パターン出してください。数字の置き方（上部・中央・全画面）を変えて比較したい。
```

### 2. タスク実行中（2番目に重要）

```
【画面2: タスク実行中】

1つのタスクだけが画面に大きく表示され、残り時間がカウントダウンしている。他のタスクは見えない。

要素:
- 実行中のタスク名（絵文字つき）
- 残り時間のカウントダウン
- 完了ボタン
- 一時停止
- （小さく）このタスクが終わったら何時になるか

重要: 「今はこれだけでいい」と感じられる画面にすること。
他のタスクが視界に入らないことが、この画面の価値そのもの。

タイマーの見せ方（数字のみ・円形プログレス・バー）で3パターン出してください。
```

### 3. 完了演出

```
【画面3: タスク完了の瞬間】

タスクを完了したときの演出。紙吹雪。

重要: 大げさすぎず、しかし確かに報われた感じ。
「よくやった」と褒めるのではなく、「終わったね」と静かに認める温度感。
名前のFin（映画の終わり）に通じる余韻を持たせたい。

アニメーションの流れを説明したうえで、ピーク時の静止画をHTMLで作ってください。
```

### 4. タスク追加

```
【画面4: タスク追加】

タスク名・所要時間の見積もり・絵文字・色を入力する。

要素:
- タスク名の入力
- 所要時間の見積もり（5分刻みなど、素早く選べる形）
- 絵文字の選択
- 色の選択
- サブタスクへの分解

重要: 入力の手数を最小にすること。ADHD層にとって入力フォームは離脱ポイント。
特に「所要時間の見積もり」は、キーボードを出さずに選べる形にしたい。
```

### 5. レポート（Pro機能）

```
【画面5: 実績レポート】

見積もりと実際にかかった時間のズレを可視化する。Pro機能。

例:「10分と見積もったタスクの平均実績は28分」

最重要の注意: これは絶対に責める画面にしてはいけない。
「あなたは見積もりが下手です」ではなく、「こういう傾向があるみたいです」という温度感。
赤字・警告色・下向き矢印は使わない。事実を静かに置く。

これはPro課金の主役機能なので、有料の価値が一目で伝わる見栄えにしてください。
```

### 6. ペイウォール

```
【画面6: ペイウォール】

サブスク登録を促す画面。

無料でできること: タスク管理、終了予定時刻、カウントダウン、当日分の履歴
Proで解放: 実績レポート、ルーティン保存、過去の履歴

重要: 煽らない。不安を作らない。カウントダウンや「今だけ」は使わない。
世界観が「責めない」なので、ペイウォールだけ攻撃的になると全部が嘘になる。

無料でも十分使えることを正直に書いたうえで、Proの価値を伝える構成にしてください。
```

### 7. オンボーディング

```
【画面7: 初回起動】

Sign in with Appleでログインしてもらう。

重要: ここが最大の離脱ポイント。
「なぜログインが必要か」を一言で納得させ、1タップで完了させること。
機能説明を何枚も見せるチュートリアルは作らない（ADHD層は確実に飛ばす）。

理想は、アプリの価値が伝わる画面を1枚見せて、すぐログインボタン。
```

### 8. App Store スクリーンショット

```
【App Store掲載用スクリーンショット】

App Storeの検索結果と製品ページに表示される画像を5枚。

1枚目（最重要・検索結果に出る）: 終了予定時刻が主役
2枚目: 1タスクだけ大写しの実行画面
3枚目: 完了演出
4枚目: 実績レポート
5枚目: ルーティン

各画像にキャッチコピーを入れてください。
1枚目のコピーは「終わる時間が、わかる。」を軸に案を複数出してください。

注意: 医療的な表現は禁止。「ADHDを治療」「症状の改善」などは使わない。
```

## デザイン確定後にやること

- [ ] 配色・タイポグラフィをデザインシステムとして固定する
- [ ] アプリアイコンを作る（金融アプリと誤解されないこと。ラマは使わない）
- [ ] ダークモード・ライトモード両方を確定
- [ ] 実装計画（writing-plans）に進む
